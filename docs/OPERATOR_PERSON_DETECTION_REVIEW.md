# Optional native operator person view

The operator recording product keeps person inference disabled by default. This
candidate adds bounded **view-only** boxes using Intel's OpenVINO CPU runtime and
Open Model Zoo `person-detection-retail-0013` FP16 model. It copies no Analytics
Lab detector, tracker or pose source and imports no `analytics_lab` package.
The separately installed Analytics Lab engineering wrapper keeps its existing
source-available restrictions; this candidate does not weaken that admission.

K5 owns its independent public-API adapter and reuses K5's existing native worker
lifecycle. Camera acquisition, live video and continuous recording remain owned
by the native media worker, independently of this optional view operation.

## View contract and limits

The product API must reauthorize the human session, current role and enrolled
camera before every frame. The broker's owner UUID is generated by the server
for one login session; it is not a browser-supplied owner or account identity.
Sign-out clears that owner's view workers. Session revocation blocks new inference
and returned results; housekeeping expires views unused for 15 seconds. Product
shutdown closes all workers.

The broker accepts tightly packed transient BGRX pixels, up to 960 pixels per
dimension and 409,600 total pixels (1,638,400 bytes). It permits four view workers,
one in-flight frame per view, at most two submissions per second, and returns at
most 32 finite normalized person boxes with confidence at least 0.5. It rejects
extra work without queuing frames. A native timeout or cancellation leaves the
underlying capacity occupied until the native worker actually completes.

Browser-supplied pixels are a presentation aid. They are not source-attested
camera evidence. Results contain no credentials, recording paths, camera URI,
producer track IDs, identity claims or retained media. They are not persisted
as detection events. Inference stops when nobody supplies frames; recording
continues independently. Do not describe this as unattended analytics, alerts,
person-down detection, identity recognition or analytic search.

Intel documents the model for upright pedestrians in retail scenes, less than
50% occlusion, with a minimum pedestrian height of about 100 pixels in 1080p.
These upstream descriptions are not K5 accuracy promises. Different poses,
small/distant people, night scenes and target camera layouts need field testing.

## Explicit local configuration

After separate local provisioning of the exact native dependencies and model
bytes, the optional operator path reads `K5_OPERATOR_PERSON_CONFIG`. The value is
an absolute path to a regular local JSON file with exactly these fields:

```json
{
  "schema_version": 1,
  "provider": "openvino-omz-person-view-v1",
  "model_revision": "6697dead54ed1cdd664b0313189c2cb52ee6335e",
  "artifact_root": "C:\\Users\\operator\\AppData\\Local\\K5PersonModels"
}
```

The artifact root contains
`person-detection-retail-0013/FP16/person-detection-retail-0013.xml` and the matching
`.bin`. An absent config means disabled. Invalid explicit config, changed bytes,
wrong versions, remote paths or unreviewed providers fail closed. Provision only
while the product is stopped; do not modify its virtual environment or models
while native inference is running. This configuration is an opt-in engineering
candidate, not an unattended installer qualification or a redistribution grant.

The repository-root Apache license applies to this official example; no extra
image license is declared in its directory. Retain the license during ephemeral
test use. The example includes annotated pedestrian boxes. It is a bounded
functional input, not an unannotated accuracy dataset. External FFmpeg only
decodes it to BGRX for this development witness and is not a runtime dependency.

`tests/integration/test_operator_beta_capacity.py` requires
`K5_OPERATOR_PERSON_ACCEPTANCE=1`, `K5_OPERATOR_PERSON_ARTIFACT_ROOT`,
`K5_OPERATOR_PERSON_FIXTURE` and `K5_DONOR_FFMPEG`. It exercises real local native
inference, a blank negative frame, independent views, overlapping work, capacity,
owner closure, idle expiry and actual worker shutdown. Its receipt contains only
aggregate counts/booleans and immutable donor IDs; no model, image or decoded
pixels are uploaded. A Windows run establishes native Windows execution only;
physical-camera, browser-alignment, endurance and accuracy acceptance stay separate.
